# OpenRemote 0.3.0

## 新的操作方式

- 控制台管理设备、配对及设置；控制端连接成功后在独立原生窗口中操作远程桌面。
- 关闭远程窗口会断开会话并释放输入；控制台继续保留。被控端在后台采集，不预览自身桌面，避免层层嵌套。
- 远控窗口内隐藏本地指针，保留视频中的远端指针，退出画面后恢复正常本地指针。它仍包含网络和视频传输延迟，不是硬件级光标预测。
- 点击远程画面后直接输入。普通字符和本机输入法完成的中文通过受限文字事件传输，快捷键和导航键使用按键事件。移除了手动「发送文字」按钮与「编辑」菜单。不会自动读取或同步剪贴板。

## 首次配对

1. 一台电脑启动连接服务，导出 `.openremote` 连接文件，通过可信渠道交给另一台电脑。
2. 本机点击「生成配对码」，获得五分钟有效的 8 位数字。
3. 另一台导入连接文件，输入对方当前配对码并提交。
4. 被请求方确认设备后批准配对。之后从设备列表直接连接。

连续五次错误尝试会关闭本轮配对。8 位设备编号只是便于识别的显示编号，不能作为身份凭据，也不保证全局唯一；底层继续固定完整公钥身份、加密并验证信令。连接文件包含公开设备身份、名称和协调地址，不包含私钥或配对码，仍不应公开提交。

已有配对可导入新的连接文件以更新临时服务地址，不重新授予已撤销权限。临时入口重启可能变更，仍不能保证两端重启后仅凭 8 位数字自动发现；没有固定协调服务时，此限制无法由短码消除。

## 从 BridgeDesk 升级

退出旧版（只关闭主窗口不会退出），再安装并打开新版，两端都建议升级。保留旧数据目录、应用标识和密钥存储命名空间，是为了延续已有设备身份与配对；界面及发行产品名均为 OpenRemote。不要同时运行旧版与新版，也不要删除旧数据目录。macOS 新版本签名变化可能需要重新授权录屏、辅助功能。

0.2.0 与 0.3.0 的已有配对保留原信令/输入协议。新的 8 位码首次配对流程要求双方使用 0.3.0。

## 本轮验证边界

已通过基础测试、隔离浏览器的合成视频/数据通道检查、中文组合事件去重、独立 Electron 会话窗口与 IPC 隔离、配对码与连接文件、临时测试身份的升级兼容检查。没有重新操作用户两台电脑做真实键鼠测试。本机 OS 中文输入法的具体候选窗行为、不同远端应用及两端实际升级后体验仍需实际使用确认。
